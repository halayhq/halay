Accounts

Add an accountits own login, no shell alias needed
Login state comes from each CLI (Claude: claude auth status, no model call), checked at startup and every 30 minutes. Accounts come from the CLIs themselves, from accounts added here, and from zsh aliases like claude-work='CLAUDE_CONFIG_DIR=… claude'.

Agent defaults

What new agents get when nothing else says: the new-agent dialog starts with these, and tasks and schedules use them. Each CLI has its own: the first block is Claude Code, one more appears for each other CLI that is installed (their modes, models and effort differ). An agent started by another agent (or by the swarm chat) inherits that agent's permission mode, and its model and effort when those are set, and can never be more permissive than it. Bots keep their own mode (manual by default) but use the model and effort here unless they set one. A cheaper model or lower effort saves usage; pick a stronger one per agent when the work needs it.

Claude Code

Model and effort "default" pass nothing, so the CLI uses your own setting. Applies to agents started after saving; change a running agent's model in its chat header menu (⋯).

Usage warnings

Warn once per day when an account's usage today reaches a threshold. Leave empty or 0 for no warning. Tokens are input + output (cache excluded). Cost is Claude Code's own estimate, and is missing for turns where it reports none.

Watchdog

Context

An agent's whole context is re-sent on every turn, so long sessions get slow and costly. The list and chat header show each agent's current context size.

Fresh context with handoff

Never touches running agents, agents waiting for an approval, or stopped agents (except the conductor). A worktree with uncommitted changes is named in the note.

Compaction and MCP

Passed to agents as CLAUDE_CODE_AUTO_COMPACT_WINDOW; Claude Code compacts a little before the context reaches it (about 88k with 100000). Applies when an agent's process next starts.

Browser (for agents)

Profiles

A profile holds the cookies and logins of every site opened in it. Treat the folder like a password manager: anyone who can read it can act as you on those sites. It is never served by the file viewer. Applies to agents started after saving; the headed setting applies when a profile's browser next starts.

Peers (other swarms)

Other swarm servers (for example on another computer in the same private network) that the swarm chat can see and drive: it can list, start and message their agents and use their task backlog. What a peer starts or adds here is marked with its name. A peer's token is its access token (its .token file); it stays on this server and is never shown again. See docs/peers.md.

Add or update a peer

Security

Passkeys are tied to the address you registered them at (the HTTPS address and localhost have separate ones). Agents and scripts keep using the access token; it signs a browser in only while no passkey exists. Lost them all? Start the server once with HALAY_RESET_PASSKEYS=1.

Plugins

Add-ons shipped with the app, plus folders and npm packages (halay-plugin-*) in . A plugin runs inside this server and this page with their full access, so enable only plugins you trust. New or updated plugin code takes effect after a server restart. See docs/plugin-authoring.md.

Server

Agents and terminals keep running and are reattached. The page reconnects by itself when the server is back.
